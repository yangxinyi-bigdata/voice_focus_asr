# Xiaomi-CocktailASR-1 初测（2026-09-22）

## 结论摘要

目标在场时，Xiaomi-CocktailASR-1 能按声纹选出说话人，正常输出时 9–13 秒片段约 1 秒完成，满足 2–3 秒显示预算。但它**不能作为目标缺席时的拒识手段**：5 个目标缺席用例全部输出了旁人的文字，没有一次返回空结果。另外，标准模式偶发“对对对……”的重复生成，一旦发生会耗尽 256 个 token 上限，单段耗时升到约 9.6 秒。

对主场景的含义：CocktailASR 可以作为“两人同时说话”片段的识别器候选，但前面必须有双麦说话人活动判定或说话人验证把关，还要加上防重复生成的保护。

## 环境

- AutoDL vGPU-32GB（Ada Lovelace，32 GB），驱动 550 / CUDA 12.4。
- torch 2.6.0+cu124、transformers 4.51.3；bf16 加载。
- 权重 `Ease3/Xiaomi-CocktailASR-1`，`pytorch_model.bin` SHA-256 `471a42ed3b4d72e1085db7ae5f6b4906cdf2cf03809040b572f141096869d15e`，与 HuggingFace 记录一致。
- 脚本：[scripts/cocktail_asr_probe.py](../../scripts/cocktail_asr_probe.py)；用例：[scripts/cocktail_realt_cases.tsv](../../scripts/cocktail_realt_cases.tsv)。
- 数据：与 PS4 初测相同的 4 段 REAL-T AliMeeting DEV 远场混合录音及其声纹样本。声纹统一截为能量最高的固定 4 秒窗口（`random_ref` 用例除外）。

## 资源与速度

| 项 | 结果 |
| --- | --- |
| 模型加载 | 52.8 秒（含 fp32 权重读入与 bf16 转换） |
| 显存 | 权重 16.5 GiB，峰值 16.6 GiB |

## 目标在场

| 用例 | 重叠比例 | 标准模式 CER | 思维链 CER | 观察 |
| --- | --- | --- | --- | --- |
| m75 / 8011 | 75% | 0.07 | 0.07 | 基本正确 |
| m85 / 8031 | 85% | 重复生成失败 | 0.08 | 标准模式陷入“对对对……” |
| m79 / 8072 | 79% | 0.44 | 0.37 | 目标内容选对，但“八点”被识别成“掰了”等 |
| m68 / 8071 | 68% | 0.19 | 0.15 | 主要是儿化和语气词差异 |

CER 为去除标点和空格后的字错误率，未做数字/汉字归一化，样本极少，只能作为方向参考。

## 声纹切换（同会议另一说话人）

- m79 改用 8071 声纹：输出“也不能太晚，太晚因为那车进出影响居民休息……”。
- m68 改用 8072 声纹：输出“但是你旁边有收费的停车场，谁也不想去交钱……”。

两者都与 PS4 声纹切换实验得到的内容一致，说明声纹条件确实生效，模型选中了另一位真实在场的说话人。

## 目标缺席

| 用例 | 输入 | 输出 |
| --- | --- | --- |
| m85 + 8011 | 另一会议的女声声纹 | 重复生成“对对对……” |
| m75 + 8031 | 另一会议的女声声纹 | 几乎完整输出该录音主说话人 8011 的话 |
| m79 + 8031 | 另一会议的女声声纹 | 输出一段混合内容 |
| m68 + 8011 | 另一会议的女声声纹 | 输出与“8072 声纹”相同的内容，即选中了录音里的女声 |
| 8011 单人语音 + 8072 声纹 | 两位不同女声 | 完整转写 8011 的话 |
| 8031 单人语音 + 自身声纹 | 目标单说对照 | 正常转写 |

拒识 0/5。官方报告的中文负样本拒识率为 68–75%，差异可能来自负样本构造方式：本次负样本声纹与录音中的说话人**同为女性**。

思维链输出揭示了模型的判断方式：先判断参考声音和各说话人的性别，再给出 1–5 的相似度分数，分数不低于 3 就认定为目标。同性别旁人很容易达到 3 分，因此被接收。对主场景而言，如果对话对象与用户同性别，单靠 CocktailASR 过滤用户声音会很不可靠。

## 参考音频截取的影响

完整声纹交给模型内部随机截取 1–4 秒时：

- m85：3 次中 1 次正确（CER 0.08），2 次重复生成失败。
- m79：3 次 CER 为 0.33、0.41、0.41，文字各不相同。

参考片段的选取会显著改变结果。正式使用时应固定参考片段，并评估不同片段的稳定性。

## 下一步

1. 加入防重复保护并复测：按片段时长限制 `max_new_tokens`（例如每秒约 8 个字），检测连续重复后截断或换参考片段重试。
2. 用双领夹麦录音测试：先用双声道能量比挡掉用户单说片段，再比较“普通 ASR”与“CocktailASR”在交替和重叠片段上的 CER。
3. 专门测量“对话对象与用户同性别”时的用户泄漏率。
4. 与 PS4 + 说话人验证在同一批录音上对照。

原始机器可读结果保存在本地 `reports/cocktail/`（Git 忽略）。
