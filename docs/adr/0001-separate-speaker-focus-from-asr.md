# 0001：目标说话人处理与 ASR 保持独立端口

状态：Accepted

## 背景

项目既要支持千问的云端说话人增强，也可能引入 WeSep、ClearerVoice 等本地语音提取模型。ASR 后端同样可能在千问 API、自建 Qwen3-ASR 和其他服务之间切换。

说话人日志、语音分离、目标说话人提取和语音识别是不同任务。把它们封装成单个厂商 Adapter 会让评测、替换和故障定位变得困难。

## 决策

核心定义两个独立端口：

- `TargetSpeakerProcessor`：拥有目标声纹准备和目标音频筛选/提取。
- `StreamingRecognizer`：拥有音频转文字和增量/最终结果发布。

`FocusedTranscriptionSession` 只编排生命周期、音频顺序和完成语义，不包含模型或网络协议实现。

若某个云端模型同时完成说话人增强和 ASR，其 Adapter 可以在内部实现组合能力，但对核心仍应适配到上述端口，避免云端事件协议成为领域模型。

## 后果

- 可分别比较“未过滤 ASR”“声纹门控 + ASR”“目标说话人提取 + ASR”。
- 可独立统计过滤错误和识别错误。
- 真实云端 Adapter 需要处理两个端口之间的共享连接；可以通过一个组合对象暴露两个窄接口。
- 多一个抽象层，但它对应真实且长期存在的能力边界。
